# rules-frozen-v5 — reproduction artefacts

Release accompanying *"Structural ROP Invariants for Static Malware Triage:
YARA Encoding, Chain-Pointer Verification, and the Prevalence of Assembled
Chains"* (Computers and Security, submission). This tag freezes every artefact
the paper's Data Availability / reproducibility section promises, so a referee
can confirm that what was released is what was run.

## Item-by-item mapping to the paper's Data Availability list

| Paper promises | Released here |
|---|---|
| the YARA rules (v5 set plus frozen v3 and v4 files) | `rules/sride_rules_v5.yar` (released set), `rules/sride_paper_rules.yar` (frozen v3), `rules/rules_v4.yar` (frozen v4), plus `rules/rules_v4_pattern_only.yar` (the Section 7.6 ablation arm) and `rules/sride_stealer.yar` (this repository's structural stealer rules) |
| the per-section entropy helper rules | the private rules `_any_section_packed` / `_no_section_packed`, embedded in `rules/rules_v4.yar` and `rules/sride_paper_rules.yar` (they use `math.entropy()` over `pe.sections[i]`, the same quantity the triage script computes) |
| the triage script | `tools/sride_triage.py` |
| the chain-pointer verifier source | `tools/sride_triage.py` (`--chain-scan`; triage and verifier are one tool by design) with `tools/make_chain_test_pe.py` (synthetic control generator) |
| the Ghidra analysis notes | `notes/` — the analysis notebooks recording the manual Ghidra stage (pivot/spine/terminator findings per family and how each became a rule) |
| the per-file corpus manifest | `manifests/corpus_results.csv` (per-file SHA-256, family, size, max section entropy, packed flag, v3 and v4 rule matches) and `manifests/corpus_ext_new14.csv` (the 14-sample 2019–2023 extension) |
| the null-model and decay experiment outputs | `manifests/null_manifest.csv`, `results/external_rules_v4.csv`, `results/external_rules_v5.csv`, `results/external_ablation.csv`, `results/external_decay.csv`, `results/chainscan_results.txt` |
| the pinned environment record with versions and SHA-256 digests | `ENVIRONMENT.txt` |

`Detection_scripts/` holds the four known-sample detectors for the stealer
families this repository tracks (Rusty, Myth, Snowflake, Prysmax) — SHA-256 +
ROP structural scan; no string indicators — and `RESULTS.md` is the
round-by-round measurement log behind every number in Section 7 of the paper.

## Malware samples are NOT redistributed

The 70 external malware binaries are referenced by SHA-256 hash only (see the
manifests); sources are documented in the paper's Appendix B. The clean
controls and null-model source binaries are vendor software (PuTTY,
Sysinternals, 7-Zip, Python, SQLite, UPX, Ninja) and are likewise not
redistributed — obtain them from the vendor sites and check against the hashes
in `manifests/null_manifest.csv`. `controls/` contains only our own synthetic
chain PEs (generated by `tools/make_chain_test_pe.py`), which are safe.

## Pinned analysis environment

Python 3.14.6 · YARA 4.5.7 · YARA-X 1.19.0 · Capstone 5.0.7 · pefile 2024.8.26
(Arch Linux x86-64, isolated VM; manual stages used Ghidra 11.0.3 and
Detect-It-Easy). The scan drivers in `scripts/` are the exact ones that
produced the reported numbers; they carry absolute paths from the analysis
machine — adjust `ROOT` to your checkout before rerunning. Rule files compile
clean on both engines (the only warnings are the single-byte atom-cost
warnings the paper itself documents in Section 5.3).
